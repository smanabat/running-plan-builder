# 2026-11-24 — MVP build checkpoint

## Context

The project moved from concept into a local-first Firebase application. The initial plan prototype remains the origin artifact; no external runner research has been performed.

## Implemented in this checkpoint

- React/TypeScript/Vite client with local email/password sign-up and sign-in.
- Firebase Auth, Firestore, Storage and Functions emulator configuration.
- Browser-side Strava CSV parsing, user-scoped upload, weekly summaries and delete controls.
- Callable function that validates plan inputs and writes a versioned marathon schedule.
- A plan dashboard showing weekly workouts, methodology version, rationale and assumptions.
- Rules that scope user data and uploads to the authenticated account.
- Architecture, product brief, methodology and decision records.
- A synthetic weekly-history fixture and sparse, inconsistent and steady-history cases. No source activity rows or direct activity derivatives are committed.

## Observations

- The planning rules are intentionally a prototype and have not been reviewed by a qualified coach.
- The current UI records experience level but does not yet use it to change the plan; this is disclosed in the plan assumptions.
- CSV uploads contain identifying source details. They are stored privately for the local emulator workflow and can be deleted in the UI. Production retention behavior remains an open decision.
- Fixtures use invented values and relative week offsets. No names, IDs, activity records, exact dates, routes, GPS, activity titles or device values are included.
